# Product Principles

> Estos principios guían todas las decisiones de producto de Creative OS.
>
> Antes de diseñar una pantalla, escribir código o incorporar una nueva funcionalidad, debemos comprobar que respeta estos principios.

---

# 1. El proyecto es el protagonista

Creative OS no gira alrededor del software.

Tampoco gira alrededor de la IA.

Todo gira alrededor del proyecto y de su capacidad para convertirse en realidad.

El software existe para ayudar al proyecto a avanzar.

---

# 2. La conversación es la interfaz principal

El usuario no debería aprender a hablar como el software.

El software debe aprender a interpretar la forma natural en la que habla el usuario.

Cada conversación debe producir estructura.

Nunca únicamente texto.

---

# 3. Organizar antes que mostrar

Mostrar información no genera claridad.

Creative OS primero interpreta.

Después organiza.

Finalmente presenta.

---

# 4. La IA acompaña. No reemplaza.

El Productor Ejecutivo nunca toma el control del proyecto.

Ayuda a pensar.

Ayuda a decidir.

Ayuda a producir.

Las decisiones importantes siempre pertenecen a las personas.

---

# 5. Todo debe generar movimiento

Cada interacción debe producir al menos uno de estos resultados:

- una decisión;
- una tarea;
- un documento;
- una conexión;
- una prioridad;
- una mejora del proyecto.

Si una funcionalidad no genera movimiento, probablemente no pertenece a Creative OS.

---

# 6. La complejidad pertenece al sistema

El usuario nunca debería cargar con la complejidad técnica.

Los motores.

Los grafos.

Los modelos.

Las relaciones.

Los cálculos.

Todo eso pertenece al software.

El usuario solamente debe sentir que está produciendo.

---

# 7. El contexto nunca debe perderse

Creative OS recuerda.

Cada conversación fortalece el conocimiento del proyecto.

El usuario nunca debería sentir que tiene que explicar dos veces la misma idea.

---

# 8. Un proyecto siempre está vivo

Los proyectos cambian.

Las personas cambian.

Las oportunidades aparecen.

Las prioridades cambian.

Creative OS debe acompañar esa evolución.

Nunca congelarla.

---

# 9. Orquestar antes que ejecutar

La función principal de Creative OS no es hacer tareas.

Es ayudar a coordinar capacidades.

Un proyecto avanza cuando las personas correctas trabajan sobre el problema correcto en el momento adecuado.

---

# 10. La información solo vale cuando produce acción

Guardar información no es suficiente.

Creative OS debe ayudar a convertir información en:

- decisiones;
- producción;
- relaciones;
- oportunidades;
- aprendizaje.

---

# 11. La confianza es un activo

El usuario debe sentir que Creative OS entiende su proyecto.

Eso requiere:

- coherencia;
- memoria;
- transparencia;
- consistencia;
- criterio.

Nunca debemos generar recomendaciones que el sistema no pueda explicar.

---

# 12. Primero claridad, después velocidad

Una recomendación clara vale más que diez recomendaciones rápidas.

La prioridad siempre será mejorar el criterio del usuario.

No simplemente responder.

---

# 13. El ecosistema amplifica el proyecto

Creative OS ayuda primero a estructurar un proyecto.

Después ayuda a conectarlo con personas, espacios, conocimiento y oportunidades.

El ecosistema nunca sustituye el trabajo del proyecto.

Lo potencia.

---

# 14. El software desaparece

El mejor momento de Creative OS ocurre cuando el usuario deja de pensar en el software y siente que simplemente está produciendo.

La interfaz debe desaparecer detrás del trabajo.

---

# 15. Construimos infraestructura, no funciones

No añadimos funcionalidades por novedad.

Construimos infraestructura que permita que nuevas capacidades aparezcan naturalmente con el tiempo.

Cada decisión debe fortalecer la arquitectura del sistema.

---

# Principio rector

Creative OS no administra proyectos.

Creative OS orquesta capacidades alrededor de posibilidades.

Toda decisión futura debe respetar este principio.
