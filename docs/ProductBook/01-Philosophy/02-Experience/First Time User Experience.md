# First Time User Experience (FTUX)

## Objetivo

La primera experiencia de Creative OS no debe sentirse como el ingreso a un software.

Debe sentirse como entrar a un estudio creativo donde alguien está dispuesto a ayudarte a convertir una idea en un proyecto real.

El usuario nunca debería preguntarse:

"¿Cómo funciona este software?"

Debería pensar:

"Qué fácil fue empezar."

---

# Principios

Toda la experiencia inicial debe transmitir cinco sensaciones.

## Claridad

Siempre debe existir un único siguiente paso.

Nunca más de una decisión importante al mismo tiempo.

---

## Cercanía

Creative OS habla como un productor creativo.

Nunca como un formulario.

Nunca como un ERP.

Nunca como un software administrativo.

---

## Progreso

Desde el primer minuto el usuario debe sentir que está construyendo algo.

Cada acción deja el proyecto en un mejor estado que antes.

---

## Confianza

Creative OS demuestra constantemente que entendió lo que el usuario explicó.

No hace preguntas repetidas.

No hace preguntas innecesarias.

---

## Inspiración

El usuario debe salir con más claridad que cuando llegó.

No solamente con información organizada.
# El recorrido ideal

La primera sesión de Creative OS tiene siete momentos.

1. Bienvenida.
2. Presentación del usuario.
3. Creación del Workspace.
4. Creación del primer proyecto.
5. Conversación con el Productor Ejecutivo.
6. Descubrimiento de las áreas del proyecto.
7. Visualización del avance y siguientes pasos.

Cada momento debe sentirse natural y continuo.

El usuario nunca debe percibir que está cambiando de módulo.

Debe sentir que el sistema avanza junto con él.
---

# La primera pregunta

Creative OS no debe empezar como un software administrativo.

No debe comenzar preguntando:

- nombre
- correo
- empresa
- cargo

Eso puede venir después.

La primera pregunta debe abrir una conversación creativa.

## Pregunta inicial recomendada

> Antes de crear proyectos, quiero entender cómo piensas.
>
> ¿Qué tipo de cosas disfrutas construir?

Esta pregunta permite que el usuario se presente desde su forma de crear, no desde sus datos administrativos.

---

# Después de la primera respuesta

Creative OS debe reconocer el tipo de usuario.

Por ejemplo:

- productor cultural
- artista
- emprendedor
- gestor social
- fundador
- consultor
- creador audiovisual
- diseñador de experiencias
- investigador
- marca o empresa

No para encasillarlo.

Sino para adaptar el lenguaje, ejemplos y preguntas futuras.

---

# Datos mínimos de entrada

Después de entender cómo crea el usuario, Creative OS puede pedir:

- nombre
- correo
- organización o estudio
- tipo de workspace

Pero estos datos deben sentirse como configuración del estudio, no como registro burocrático.

---

# Regla de entrada

El usuario no entra a un formulario.

Entra a una conversación que abre su espacio de producción.
